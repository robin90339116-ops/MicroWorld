## 2. 统一产品定义

SmallWorld 不是普通聊天软件、传统交友 App、纯 AR 游戏或普通点评平台。它是一套以真实地点和真实共同经历为基础的线下兴趣社交产品。

核心关系链路：

`发现地点或活动 -> 到达现场 -> 完成签到、任务或碰触 -> 形成真实共同经历 -> 双方确认关系 -> 低打扰聊天 -> 再次参与`

核心内容链路：

`真实地点 -> AR 任务/故事 -> 用户小世界 -> 共同建设 -> 足迹与荣誉沉淀`

核心评价链路：

`真实到场 -> 手机碰手机 NFC 或备用验证 -> 生成一次性凭证 -> 提交五维评价 -> 行为数据加权 -> 探索页展示可信评分`

### 2.1 不可破坏的产品规则

1. 聚焦线下兴趣社交，而不是线上随机匹配。
2. 未真实见过或共同互动的人不能直接建立强关系。
3. 双方确认后才开放聊天。
4. 附近的人默认只展示兴趣、共同来源和互动意愿，不直接暴露私人资料。
5. 到场后才解锁完整 AR、隐藏任务、现场成员和深层小世界内容。
6. 评价必须优先由真实行为证明，不能退化为任意用户随手打星。
7. AI 不得绕过到场、隐私、双向确认和安全规则。
8. 用户必须可以隐身、暂停被发现、举报、拉黑和快速求助。

### 2.2 目标用户

- 18-35 岁城市年轻人。
- 留学生、海外华人和刚搬到新城市的人。
- 咖啡、读书、摄影、运动、桌游、音乐、艺术、城市探索等兴趣参与者。
- 想认识新朋友，但排斥陌生私信、尬聊和高压社交的人。
- 活动主理人、兴趣俱乐部和本地场馆。

### 2.3 首发建议

- 首发城市：墨尔本。
- 首发区域：CBD、Carlton、Clayton、Box Hill、South Yarra 及主要高校周边。
- C 端首发场景：咖啡、读书、桌游、城市探索。
- 组织者试点场景：羽毛球、乒乓球或棋牌小型活动。
- 活动规模：每场 6-20 人，优先公共地点和小局。

## 3. 产品信息架构

### 3.1 探索

目标：帮助用户判断附近哪里值得去、适合什么兴趣、社交压力如何，以及是否存在活动、AR 和小世界。

必须包含：

- 城市定位、高德地图、地点标记和当前位置。
- 地点、兴趣、活动搜索。
- 兴趣和距离筛选。
- 地点与活动推荐。
- 综合评分及五维评分：
  - 社交舒适度
  - 兴趣匹配度
  - 安全感
  - 活动质量
  - 小世界丰富度
- 真实碰触评价数、到场数、复参率和可信等级。
- 地点详情、路线规划、系统导航和 AI 路线入口。

当前完成状态（2026-06-14）：

- 地点和地标详情已加入简介、开放时间、空间特点、进行中/即将开始的活动与比赛。
- 活动和比赛具有独立详情页，展示组织者、地点、参与人数、形式、奖励和规则。
- 公共聊天与内容分享收敛到地点详情中的“地点广场”，不进入全局聊天 Tab。
- 每个地标已加入本周贡献、活动比赛、真实到场三类排行榜。
- 每个地标已加入 NFT 奖牌展示模式，支持稀有度、发行量、解锁进度、唯一凭证编号和公开元数据。
- 奖牌领取由真实 NFC 碰触、可信评价、比赛成绩或地点共建记录驱动，并要求当前地点页凭证有效。
- 当前 NFT 状态为 SmallWorld 数字藏品凭证，公链合约、钱包托管与链上铸造仍属于后续发布基础设施。
- 后端通过短时地点房间令牌强制校验；离开、切换地点或令牌过期后不能继续公共发言。

### 3.2 兴趣

目标：帮助用户系统了解一个兴趣如何入门、如何学习、在哪里参与，以及附近有哪些相关俱乐部和真实地标。

必须包含：

- 兴趣、学习方法、俱乐部和关键词检索。
- 人文、艺术、运动、技能、城市、桌面和自然等分类筛选。
- 兴趣简介、零基础难度、建议学习周期和社交方式。
- 分步骤学习路径、入门工具和准备事项。
- 兴趣名下的本地俱乐部、活动时间、参与门槛和认证状态。
- 每个兴趣关联真实地标，用户可以直接进入地点详情、查看活动并规划路线。

当前完成状态（2026-06-14）：

- 底部第二个 Tab 已由“实景”替换为“兴趣”。
- 已完成兴趣搜索、分类筛选、兴趣详情、学习路径、入门工具、俱乐部和关联地标。
- 已建立阅读、摄影、咖啡、桌游、跑步、音乐、城市探索和手作等首批兴趣数据。
- 俱乐部和兴趣地标可直接进入现有地点详情，继续使用地点活动、公共空间、排行榜和奖牌能力。

### 3.3 世界

目标：把到场后的实景互动与可访问、可共同建设的 3D 私有空间统一在同一个模块。

实景现场必须包含：

- HarmonyOS CameraKit 实时画面和全屏预览。
- 当前地点及 GPS + QR 到场验证状态。
- AR 宝藏、小世界入口、地标故事和破冰任务。
- 附近愿意被发现的同兴趣用户。
- 扫描、任务、现场成员和安全入口。

正式 AR 需要真实空间锚定、方向/距离计算、节点命中和内容加载，不能仅使用固定坐标 UI 标签。

内容类型：

- 虚拟空间
- AR 宝藏
- 地标故事
- 任务
- 留言墙
- 共同建设空间

必须支持草稿、发布、地点绑定、到场可见、公开/邀请可见、内容管理、举报审核和共建权限。

- 已完成基于 HarmonyOS `ArkGraphics3D` 的真实 3D 世界视图，支持单指轨道视角旋转、双指缩放和视角重置。
- 已完成基础物件库、三维物件放置、地面拖动、高度调整、三轴数据、缩放、旋转、删除和服务端持久化。
- 已完成旧二维世界数据到三维坐标的兼容映射，现有用户世界无需清空或重建。
- 已完成按注册邮箱邀请共建者，共建者可进入同一个世界继续建设。
- 已完成 OpenAI-compatible AI 图像物件接口；未配置外部图像服务时自动生成可编辑预览物件。
- 已完成世界列表、3D 详情、3D 建设模式、物件选择器和 AI 创造前端。
- 已定义厂商无关的 `WorldSpatialDisplayAdapter`，为手机 AR、眼镜 AR、透视 MR 和沉浸式 MR 提供统一扩展入口；当前尚未接入具体设备 SDK。

### 3.4 聊天

目标：延续真实共同经历，而不是制造新的陌生人私信入口。

每个会话必须展示关系来源：

- 见于哪个地点。
- 共同参加的活动。
- 共同完成的任务。
- 共同小世界。
- 共同兴趣。

聊天规则：

- 未满足关系条件不能创建私聊。
- 一次见面最多发送一次连接请求。
- 对方未回应时不能连续追发。
- 支持仅活动消息、静音、举报、拉黑和解除关系。
- 默认降低已读和在线状态压力。

### 3.5 我

必须包含：

- 虚拟身份和头像。
- 兴趣标签与社交意图。
- 线下足迹和真实见过的人。
- 徽章、数字荣誉和活动证书。
- 收藏地点和我的小世界。
- 隐身、今天不想被发现、位置授权和数据删除。
- 黑名单、举报记录、到场验证记录和安全中心。

## 4. 扩展产品线

### 4.1 手机碰手机 NFC 真实评价

两台手机分别进入 HCE 被碰模式和 Reader 读取模式，通过 ISO-DEP/APDU 交换一次性令牌。后端确认双方身份、设备、地点、时间和防重放信息后生成碰触凭证。只有凭证参与者可以提交一次评价。

评价系统不是简单平均分。建议综合：

- 到场验证。
- NFC 硬件碰触。
- 活动参与和复参。
- 社交图谱自然度。
- 历史评价稳定性。
- 评价内容完整度。
- 账号和设备成熟度。

完整公式和反作弊阈值只保留在服务端。

### 4.2 活动、俱乐部与场馆

策划书中的完整商业闭环还包括：

- 活动发布、报名、候补、取消和签到。
- 主理人创建空间和生成签到二维码。
- 比赛分组、对阵、比分双向确认、排名和段位。
- 数字奖杯、证书、连续参与徽章和品牌联名荣誉。
- 俱乐部成员、复参率和活动数据。
- 场馆活动日历、优惠券、客流与会员转化。
- 组织者后台和商家后台。
- 活动服务费、SaaS 订阅、场馆导流及品牌合作。

这部分属于完整商业版本，不应与首发 C 端 MVP 混在同一迭代中一次完成。

### 4.3 AI 线下导游

AI 导游是跨探索、兴趣、地点详情、世界实景现场和聊天的能力，不增加普通聊天式第六个底部 Tab。

主要能力：

- 根据时间、距离、兴趣和社交压力生成城市路线。
- 到场前提供准备信息，到场后解锁现场讲解和任务。
- 在实景画面提示当前节点。
- 提供可跳过的低压力破冰建议。
- 将足迹整理成地标故事或小世界草稿。
- 所有事实展示来源、内容版本和更新时间。
- 不向模型提供未授权的附近用户身份和精确位置。

### 5.2 已有代码但仍属于演示级

#### 探索和地图

- 地点只有三个固定墨尔本示例。
- 搜索框和兴趣筛选主要是 UI，未连接真实搜索和后端查询。

#### 相机和 AR

- CameraKit 实时预览和全屏已实现。
- 当前 AR 宝藏、任务和小世界入口是固定屏幕位置的 UI 叠层。
- 尚无真实空间追踪、平面识别、图像识别、姿态估计、地理锚点和命中测试。
- 尚无现场扫描结果、任务状态和奖励写入后端。

#### NFC 评价

- 已有真实 HCE/Reader/APDU 交换方向和后端一次性令牌。
- 当前用户 ID、设备 ID 在 App 启动时临时生成，重启后身份变化。
- 客户端目前直接把 `gpsVerified` 设为成功，不是服务端可验证的真实位置证据。
- `repeatVisit` 和评价文字目前是固定演示值。
- JSON 文件存储不支持并发、事务、审计和可靠恢复。
- 尚无登录令牌、设备证明、签名挑战、限流、异常图谱检测和人工复核。
- 尚未完成多型号 Huawei 手机的 NFC 兼容性测试。
- 尚未实现策划书要求的二维码备用流程。
- 因设备和系统能力差异，不能在完成兼容矩阵前宣称所有手机都支持手机碰手机。

因此，当前 NFC 系统可以称为“真机技术 MVP”，不能称为“生产级真实评价系统已完整完成”。

#### 关系和聊天

- 页面和交互路径已存在。
- 成员、关系和消息仍为内置静态数据。
- 未持久化见面事件、连接请求和关系状态。
- 未实现真实消息发送、实时同步、离线消息、推送和会话权限校验。
- 未实现举报、拉黑、解除关系和风控处理闭环。

#### 世界和个人资料

- 世界创建、基础物件、AI 物件、草稿、发布、地点绑定、访问权限和共建权限已写入后端。
- 当前建设画布是 2D/2.5D 可交互编辑器，不是完整 3D 体素世界。
- 尚无媒体对象存储、世界版本历史、留言/任务/AR 节点编辑器、举报和审核。
- 身份、兴趣、足迹、徽章和收藏未持久化。

## 6. 当前最高风险

### P0 安全风险

1. 高德 Key 目前直接写在客户端源码中。
2. 本地工程配置中包含签名材料路径和签名口令，不应进入版本库或共享包。
3. 后端使用局域网 HTTP 地址，没有 TLS、鉴权和环境配置。
4. 客户端身份是临时随机值，无法形成真实账号、关系或防作弊依据。
5. 服务端信任客户端传来的 GPS 布尔值，无法证明真实到场。

处理要求：

- 立即轮换曾暴露的 Key 和签名口令。
- 将机密配置移出源码和版本控制。
- 建立 `dev/staging/prod` 环境配置。
- API 全部使用 HTTPS 和用户访问令牌。
- 服务端保存可审计的到场、碰触和评价事件。

### P0 产品风险

- 当前首页展示了大量功能，但核心数据仍是静态演示数据。
- 如果先扩展 AR、AI 和商业功能，而账号、活动、到场、关系四个基础实体还未稳定，会反复返工。
- 必须先跑通“发现 -> 到场 -> 见过 -> 双向确认 -> 聊天 -> 复参”的真实闭环。

## 7. 推荐技术架构

### 7.1 HarmonyOS 客户端

当前 `Index.ets` 承担页面、数据、地图、相机、NFC 和网络逻辑，应逐步拆分：

- `features/auth`
- `features/explore`
- `features/place`
- `features/checkin`
- `features/nfc`
- `features/scene`
- `features/world`
- `features/relationship`
- `features/chat`
- `features/profile`
- `features/ai-guide`
- `shared/network`
- `shared/storage`
- `shared/design-system`
- `shared/permission`

使用统一路由、状态管理、Repository 层和环境配置，避免继续在单文件中堆叠功能。

### 7.2 后端

首发阶段使用 TypeScript 模块化单体即可，不急于拆微服务。

核心模块：

- Auth：账号、登录、令牌和设备会话。
- User/Profile：兴趣、意图、虚拟身份和隐私。
- Place/Explore：地点、地图查询、评分和搜索。
- Activity/Attendance：活动、报名、签到和到场证明。
- Encounter/Relationship：见面事件、连接请求和关系等级。
- Chat：会话权限、消息、撤回、举报和推送。
- World/UGC：世界、内容、任务、留言和共建。
- NFC/Review：会话、硬件证明、评价和可信权重。
- AI Guide：路线、知识、会话、引用和安全策略。
- Moderation：审核、举报、拉黑和申诉。
- Organizer/Admin：主理人、场馆和运营管理。

基础设施建议：

- PostgreSQL + PostGIS：业务数据、地理查询和关系事件。
- Redis：会话、限流、短期 NFC 令牌和任务队列。
- 对象存储：头像、地点图、世界内容、举报证据。
- WebSocket 或受控实时通道：聊天和现场状态。
- HarmonyOS Push Kit：连接请求、活动提醒和消息通知。
- 审计日志和监控：关键安全事件不可直接覆盖。

## 9. 分阶段开发计划

## Phase 0：工程与安全基线（1-2 周）

目标：让工程可以安全地持续开发和多人协作。

任务：

- 轮换并移除源码中的 Key、口令和本机路径。
- 补充 `.gitignore`，排除签名材料、构建目录、IDE 缓存和本地数据。
- 增加环境配置和 API Base URL 管理。
- 将 `Index.ets` 拆成页面和服务的基本目录。
- 建立错误处理、日志、网络状态和权限状态组件。
- 建立 CI：ArkTS 编译、后端检查和基础测试。

验收：

- 仓库中不存在明文机密。
- 新机器可按 README 构建。
- Debug 和 Release 配置分离。
- 每次提交自动执行构建检查。

## Phase 1：真实账号、地点、活动和到场（4-6 周）

目标：跑通第一个真实业务闭环的前半段。

任务：

- 注册登录、访问令牌、稳定用户 ID 和设备会话。
- 兴趣、社交意图、头像和隐私偏好持久化。
- 地点和活动数据库。
- 探索搜索、筛选、地图动态标记和实时距离。
- 地点详情、活动报名、收藏和导航。
- GPS 地理围栏 + QR 签到。
- 到场证明及“今日见过的人”生成。
- 运营后台录入地点和活动。

验收：

- 用户重启 App 后身份和数据不丢失。
- 地图和列表来自同一后端数据源。
- 未到场不能查看现场成员或解锁现场任务。
- 每次到场都产生服务端审计记录。

## Phase 2：关系、低打扰聊天和安全（3-5 周）

目标：完成 SmallWorld 最核心的社交闭环。

任务：

- Encounter 见面事件。
- 关系三层状态：同场出现、确认见过、建立联系。
- 双向连接请求和关系来源。
- 低打扰聊天权限。
- 消息发送、历史、离线同步和推送。
- 举报、拉黑、解除关系、隐身和“今天不想被发现”。
- 安全按钮、紧急联系人和运营处置后台。

验收：

- 没有 Encounter 的用户无法创建私聊。
- 双方未同意前不能绕过服务端发送消息。
- 拉黑后双方立即不可再互动。
- 每个会话都能追溯到地点、活动、任务或世界。

## Phase 3：生产级 NFC 真实评价（3-5 周）

目标：把当前技术 MVP 升级为可试点的真实评价系统。

任务：

- NFC 会话绑定登录账号和注册设备。
- 服务端生成随机挑战和短时令牌。
- APDU 请求和响应增加签名、时间戳和防重放字段。
- 使用真实 LocationKit 数据生成位置证据，不接受客户端自报布尔值。
- 双方地点、时间窗口和设备差异校验。
- 评价表单支持真实文字、五维评分和是否复参。
- QR 备用验证。
- 限流、设备异常、碰触聚集、评价集中度和重复关系检测。
- Huawei 真机兼容矩阵和现场失败恢复。
- 评分快照、权重版本和申诉后台。

验收：

- 两部不同登录账号、不同设备才能生成凭证。
- 令牌过期、重复使用、远程复制和同设备自碰被拒绝。
- GPS、NFC、账号和时间证据均由服务端验证。
- 每个参与者对一次凭证最多评价一次。
- NFC 不可用时可通过受控 QR 流程完成。
- 至少覆盖计划用于试点的真实机型。

## Phase 4：小世界和真实 AR（4-6 周）

目标：让真实地点上的虚拟内容可以被创建、发现和完成。

任务：

- 世界创建、编辑、草稿、发布和删除。
- 世界与地点、作者和共建者绑定。
- 留言墙、地标故事、任务和 AR 宝藏。
- 媒体上传、压缩和审核。
- AR 节点坐标、方向、距离和现场命中。
- 任务参与、共同解锁和奖励。
- 到场可见、公开可见和仅邀请可见。
- 内容举报、版权和运营审核。

验收：

- 用户创建的内容能在另一台设备和正确地点加载。
- 未到场用户不能访问隐藏内容。
- AR 标记随设备方向和位置变化，不是固定屏幕贴纸。
- 任务完成状态由后端记录且不可直接伪造。

## Phase 5：AI 线下导游 MVP（4 周）

目标：完成地点导览、兴趣路线和现场问答。

任务：

- 探索页 AI 路线入口。
- 路线偏好：时间、距离、兴趣和社交压力。
- 地点知识库、来源和内容版本。
- AI 路线结构化输出。
- 导览会话、节点进度和到场解锁。
- 地点问答和 TTS。
- 实景节点提示。
- 足迹总结和小世界草稿。
- 隐私最小化、内容安全和纠错反馈。

验收：

- 路线节点全部来自 SmallWorld 真实地点数据库。
- 距离和时间可由地图验证。
- 事实性讲解包含来源或更新时间。
- 关闭位置权限后明确降级。
- AI 不接收或泄露附近用户私人信息。
- AI 生成内容发布前必须经用户确认。

## Phase 6：俱乐部、比赛和数字荣誉（6-8 周）

目标：落地《在场》策划书中的组织者工具和商业试点。

任务：

- 主理人认证和俱乐部管理。
- 活动创建、报名、候补、签到和收费。
- 循环赛和单败淘汰赛。
- NFC 对手确认和比分双向确认。
- 排名、胜率、积分和段位。
- 数字奖杯、证书和分享卡。
- 组织者数据：到场率、复参率、活动完成率和收入。
- 场馆页、优惠券和会员转化。

验收：

- 主理人可以不用微信群接龙和 Excel 完成一场活动。
- 报名、签到、赛程、比分、排名和发奖形成完整闭环。
- 比分必须双方确认或由主理人仲裁。
- 活动和场馆评价只开放给真实参与者。

## Phase 7：Beta、运营和发布（4-6 周）

目标：从“功能完成”进入“可以公开试点”。

任务：

- 单元、接口、UI、双机 NFC、弱网和恢复测试。
- 性能、耗电、内存、相机、地图和后台定位测试。
- 渗透测试、权限审计和隐私评审。
- 内容审核 SOP、举报 SLA 和安全事件处理。
- 数据备份、迁移、监控、告警和灾难恢复。
- 用户协议、隐私政策、社区规范和账号注销。
- AppGallery 发布材料和商店审核。
- 3-5 个合作地点、5-10 场活动的现场试点。

验收：

- 无 P0/P1 阻断缺陷。
- 核心接口有监控和告警。
- 关键数据可备份和恢复。
- 现场 NFC/QR 签到成功率达到试点目标。
- 用户能够完整完成核心闭环并愿意参加下一次活动。

## 10. 测试计划

### 客户端

- 页面导航、状态恢复和安全区。
- 不同尺寸手机、横竖屏和字体缩放。
- 地图加载失败、Key 失效、无网和定位被拒绝。
- 相机权限、锁屏、切后台、全屏切换和资源释放。
- NFC 关闭、不支持、碰触超时、重复碰触和异地碰触。
- 聊天断线、重复发送和消息顺序。

### 后端

- 认证、授权、越权和数据隔离。
- NFC 令牌过期、重放、伪造和并发提交。
- 一次凭证一次评价。
- 评分权重版本回归测试。
- 地理范围、时间窗口和异常图谱。
- 数据迁移、备份和恢复。

### 现场测试

- 不同手机 NFC 天线位置。
- 戴壳、弱网、无网和高人流环境。
- GPS 漂移和室内定位误差。
- 主理人协助和 QR 备用流程。
- 用户是否能在 3 秒内理解碰触动作。
- 用户是否清楚评分为何被解锁。

## 11. 上线 MVP 范围

为了尽快得到真实反馈，建议第一版公开试点只承诺：

1. 登录和虚拟身份。
2. 探索地点及活动。
3. 地图、筛选、地点详情和导航。
4. GPS + QR 到场。
5. 今日见过的人。
6. 双向确认关系。
7. 低打扰聊天。
8. 举报、拉黑和隐身。
9. 一个地点的小世界留言/任务。
10. NFC 真实评价作为受控试点功能。

第一版暂不承诺：

- 完整 3D 世界。
- 所有手机通用的 NFC 碰手机。
- 大规模比赛系统。
- 支付和复杂商家后台。
- 自动发布的 AI 内容。
- 多城市同时运营。

## 12. 完整 App 的完成定义

SmallWorld 不能只以“页面都能点开”作为完成标准。完整 App 至少必须满足：

- 所有核心数据来自真实后端并可跨设备持久化。
- 到场、见面、连接、聊天和评价规则由服务端强制执行。
- 未见过的人无法绕过客户端限制私聊。
- NFC/QR/GPS 证据可审计并具备防重放能力。
- 地图、相机、AR、聊天和推送在真机稳定工作。
- 小世界内容有发布、权限、审核和举报闭环。
- AI 导游有来源、隐私控制和安全降级。
- 用户可以管理授权、导出/删除数据和注销账号。
- 运营人员可以管理地点、活动、举报和异常评价。
- 有自动化测试、监控、备份、隐私文档和发布流程。

## 13. 下一步执行顺序

当前最合理的开发顺序：

1. 完成 Phase 0：安全、环境配置和代码拆分。
2. 完成真实账号、地点、活动和到场。
3. 完成 Encounter、双向关系和聊天。
4. 将 NFC 从技术演示升级为绑定真实身份的试点系统。
5. 再扩展真实 AR、小世界和 AI 导游。
6. 最后进入俱乐部、比赛、数字荣誉和商业后台。

短期第一项开发任务建议定义为：

`建立 SmallWorld 正式后端基础，完成登录、用户、地点、活动、到场证明五个模块，并把探索页的固定数据全部替换为 API 数据。`
