# 本机签名与历史清理

## 新克隆的配置方式

用编辑器将根目录 `build-profile.example.json5` 另存为 `build-profile.json5`，再在 DevEco Studio 的项目签名配置中使用自己的账号与设备生成签名。不要覆盖已有本机配置。模板保留工程 SDK 和模块设置，不包含密码、证书路径或签名引用；模板本身不能替代真机签名。

根目录 `build-profile.json5` 已加入忽略规则。不要强制加入 Git，也不要上传 AGC 文件、私钥、签名材料或业务数据库。

## 2026 年 9 月 11 日历史清理

项目级签名配置从分支历史移除，保留无凭据模板。提交标识已变化，旧文档中的提交号属于清理前记录，不宜通过合并旧分支恢复。代码行为不在本次清理范围内。

已经克隆的开发者应保存未提交工作，在新的目录重新克隆。不要把旧历史强制推回远端。原本机签名文件可单独保留，但不应重新提交。旧克隆和备份依然可能包含原密码，需要按敏感数据保管。

## 公开前仍需由所有者处理

- 在华为开发者平台及本机签名管理中吊销或替换受影响的证书与配置；不要在聊天中提供密码。
- 检查旧 Actions 日志、制品、PR 引用和其他克隆；分支强制推送不会自动清除它们。
- 如旧提交或缓存仍能访问敏感内容，联系 GitHub 支持协助清理，不以修改可见性代替处理。
- 完成上述事项并确认后再公开。模式扫描只能发现部分秘密类型，不是对全仓库绝无秘密的保证。
