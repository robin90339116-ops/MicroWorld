# 数据状态备份与隔离恢复

本工具用于当前单行 JSONB 数据模型，只导出业务状态，不是整个数据库、角色权限、商家登记文件、证书或链服务的备份。不会调用 store.init，也不会在源表丢失时重建数据。

## 操作

先通过安全环境配置 SMALLWORLD_DATABASE_URL 和可信 CA；源表默认 microworld_state，可用 SMALLWORLD_DATABASE_TABLE 指定。不要把连接串放在命令参数、聊天或 Git 中。以下目录需事先创建并限制访问。

```sh
cd backend
npm run db:backup -- export /安全备份目录/microworld-2026-09-10.mwbackup.json
npm run db:backup -- restore /安全备份目录/microworld-2026-09-10.mwbackup.json microworld_restore_20260910
```

- 导出使用单次 SQL 读取已提交快照，输出格式有版本和 SHA-256 校验；限制 64 MiB。通过临时文件同步后独占发布，拒绝覆盖已有文件或符号链接；文件权限 0600。
- 备份可能包含账号、密码散列、登录会话、聊天等敏感数据。0600 不是加密；需要另行加密、异地保管并管理保留期。不要上传备份作测试制品，不要提交 Git。仓库忽略 *.mwbackup.json 与 backend/backups/，自定义其他位置仍须自行确认。
- SHA-256 仅检测意外损坏，不验证来源身份，不抵抗有能力同时篡改内容与校验值的人。只恢复可信来源的备份。
- 恢复先验证文件，再在事务内 CREATE TABLE / INSERT / COMMIT；目标必须不存在，不提供覆盖开关。已有表、非法表名、损坏文件均拒绝。提交回执丢失会报告结果不确定，不自动重试；先查目标表再决定下一步。
- 恢复后的账号和登录会话也是备份时点的数据。只在隔离环境验收；正式切换前需评估备份后的数据差异、会话撤销、外部支付/链记录一致性。不要让测试环境调用生产外部服务。
- 本工具不自动改 SMALLWORLD_DATABASE_TABLE、不停服、不切换流量。生产切换需要单独制定停写、差异核对、回退和权限方案。
- 若导出发布后目录同步失败，命令可能报告失败但完整文件已存在；先校验该文件，不删除已有文件后盲目重试。

## 验收范围

单元测试覆盖内容往返、损坏/版本拒绝、0600、已有文件/符号链接拒绝、恢复前验证、SQL 回滚及提交不确定性。实库 test:db 会使用随机临时表验证导出恢复及恢复后写入，并检查重复恢复不会覆盖已有状态。

这不是生产备份恢复演练；尚未提供定时备份、加密密钥管理、异地存储、保留策略、时间点恢复或云端实例快照配置。
