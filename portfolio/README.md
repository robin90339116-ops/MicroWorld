# MicroWorld 微世界

### 把一次线下相遇，变成有共同来源的连接

![MicroWorld 产品案例封面：从相遇、确认到连接与纪念](media/cover.svg)

**产品经理项目案例 · 独立项目 · HarmonyOS 原生 App 原型**

展示更新：2026-09-10｜实现核对基线：`3ca147f`

MicroWorld 探索一个具体问题：在线下兴趣活动或商家场景中，如何让用户把一次相遇延续为有来源、经确认的连接？方案以 NFC「碰一碰」作为交互入口，把个人关系建立与商家到店评价分成两条链路，并为确认、取消、重试和奖励设计明确规则。

项目尚处于实现与验证阶段，没有已证实的市场需求、用户增长或商业化成绩。NFC 交互记录不等于不可伪造的到场证明。

## 30 秒速览

| 维度 | 项目内容 |
|---|---|
| 目标用户假设 | 希望延续线下兴趣交流的参与者；希望区分到店与消费评价的商家 |
| 首要场景 | 两人在同一兴趣活动认识，希望互相确认后保留联系方式与相遇来源 |
| 产品主张 | 先共同经历，再经双方确认建立连接；不依靠单方操作自动成为好友 |
| 我的职责 | 产品定义、核心流程与规则设计、需求优先级管理、设计与实现核对、技术可行性及交付验收 |
| 当前交付 | 鸿蒙原型及后端实现、个人/商家两套会话机制、可追溯的自动验收、数据库与部署准备 |
| 待验证 | 用户是否需要这一额外动作；双机体验；真实地图、支付、云部署与上链 |

## 三个值得讨论的产品决策

1. **为什么不能把「碰到」直接等同于「愿意加好友」？** 物理接近与社交同意是两件事，因此保留双方确认与取消机会。[查看取舍](decisions.md#d02)
2. **为什么将地点评价与商品评价分开？** 到店证据不能证明真实购买；缺少支付核验时，商品评价保持关闭。[查看取舍](decisions.md#d03)
3. **为什么「结果未知」不能直接再发一次奖励？** 用户重试不应变成重复扣款或重复发奖，因此先查原结果、恢复原快照。[查看取舍](decisions.md#d04)
