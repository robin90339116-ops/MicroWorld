# 用户验证与指标计划

[返回展示首页](README.md) · [主持脚本](research/session-guide.md) · [记录模板](research/observation-template.md)

## 当前证据状态

- 已有：代码、设计规格、版本提交、自动验收记录。
- 尚无可核验资料：目标用户访谈原始记录、真实双机任务观察、线上使用数据、付费/留存结果。
- 本次交付的是可执行研究方案，不是已经执行的研究。未填写用户人数、满意度或转化提升。

## 第一轮要回答的三个问题

| 假设 | 如何验证 | 什么结果会促使调整 |
|---|---|---|
| H1：相遇来源比单纯加好友有额外价值 | 询问最近一次真实经历，再让用户比较两种流程 | 用户持续认为直接加好友足够，无法描述额外用途 |
| H2：用户理解“碰触不等于同意加好友” | 无提示完成确认/取消任务，观察解释是否正确 | 用户误以为已自动加好友，或找不到拒绝机会 |
| H3：纪念记录具有独立价值 | 暂不突出积分，询问会在什么情况下再次查看 | 用户只有在奖励刺激下才愿意操作，不需要记录本身 |

假设失败不等于产品必须继续加功能；应考虑收缩到活动签到/纪念等更具体场景，或承认直接加好友更适合目标用户。

## 样本与执行顺序

**建议第一轮招募 5–8 位目标参与者，不是已招募人数。** 优先选择近期参加过读书、运动、咖啡等线下活动、确有认识新朋友经历的人，包含愿意和不愿主动交换联系方式者。小样本只定位问题，不估计整体市场比例。

先做原型可理解性测试，再做双机可用性测试。前者不需要真实 NFC，也不能证明 NFC 成功率。商家研究单独招募，不混入个人用户样本计算一个平均值。

## 任务与观测

1. **T1：理解入口。**说明产品能帮你完成什么、不帮你完成什么。
2. **T2：首次连接。**你愿意继续认识对方，请完成连接并找到聊天入口。
3. **T3：改变主意。**对方已发起，但你不想连接，请停止流程。
4. **T4：结果未知。**提交后网络中断，请判断下一步；原型阶段口头说明情境，真机阶段才实际断网。
5. **T5：再次查看。**寻找刚才的相遇结果，解释奖励是否会因重试重复发放。

主持人不告诉用户该点击什么。每次提示都记录，否则不能把有提示完成算作独立成功。

## 指标口径（待采集，不代表已埋点）

| 指标 | 口径 | 用途与注意事项 |
|---|---|---|
| 独立完成率 | 无提示完成核心任务的人数 / 实际开始任务人数 | 同时报人数和分母；不要用小样本推断全体用户 |
| 双方连接完成率 | 服务端 confirmed 会话数 / 有效发起会话数 | 仅真机/线上版本可采集；重试去重；区分主动取消与技术失败 |
| 完成耗时 | 从两端准备好到双方确认成功的时间 | 同时报中位数、范围、失败数；不能只统计最快成功样本 |
| 关键误解数 | 误以为单方已建立连接、重复领奖等观察次数 | 保留行为与原话，区分主持人推断 |
| 恢复成功率 | 成功查回原结果的中断任务 / 可恢复中断任务 | 单独记录不可恢复窗口；未提交与已提交场景分开 |
| 再次使用意愿 | 在具体下一次场景中愿意使用的表述及理由 | 意愿不是留存；需要后续实际使用观察 |

建议的事件字典：session_started、peer_read、confirmation_submitted、session_confirmed、session_cancelled、recovery_requested、recovery_resolved。仅为待实现方案；事件采用非敏感关联 ID，不记录 NFC 令牌、挑战、精确坐标或聊天内容。

## 第一轮决策门槛（内部试验标准，非行业标准）

- 任何用户把拒绝理解为已经加好友，或系统出现未经同意的连接：列为阻断问题，修复后复测。
- 如多数参与者不能说明相比直接加好友的额外价值：先重做定位，不优先投入真实上链。
- 原型阶段确认关键任务可理解后，再扩大真机测试；不以原型顺畅替代硬件成功率。
- 产品判断保留反例。报告格式为“观察 → 解释假设 → 修改建议 → 复测结果”，不从一句赞美推出需求成立。

## 数据与隐私

取得录音/录屏同意后再记录；不把参加测试等同于同意公开。使用 P01 等匿名编号，不在公开仓库存联系方式、完整录音、精确地点或原始聊天。公开案例只使用经许可的脱敏摘要，原始记录保存在受控位置。
