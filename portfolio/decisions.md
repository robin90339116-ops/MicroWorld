# 产品决策记录

[返回展示首页](README.md)

这里区分「已落地的规则」与「待用户验证的判断」。后续证据推翻判断时，应修改方案，而不是补写支持原结论的研究。

## D01｜NFC 是显式交互入口，不是绝对到场认证

- **问题：**如何让一次线下接触有可识别的动作与来源？
- **备选：**直接加好友成本最低；二维码易理解；蓝牙可做附近发现；NFC 强调主动靠近。没有完成四种方式的实测比较，不能声称某一方案最优。
- **当前选择：**实现 NFC HCE/ISO-DEP 入口，加服务端限时会话及双端匹配。
- **代价：**设备支持和操作准备要求较高，可能降低完成率；仍无法排除中继、串通和改造客户端。
- **重新评估条件：**用户不理解额外价值，或真机失败/耗时明显影响核心任务。不能将“4cm”当成无条件安全保证。

<a id="d02"></a>

## D02｜双方确认优先于熟人免确认

- **问题：**靠近是否等于同意建立关系或留下记录？
- **历史方案：**首次确认，熟人再次碰面免确认。
- **当前实现：**首次及后续均由双方显式确认，统一拒绝、取消与恢复语义。
- **取舍：**增加操作成本，换取意愿边界和结果归属更清晰。
- **待验证：**熟人是否认为该步骤重复；如考虑快捷模式，必须先设计可理解的授权、关闭与撤回方式。

<a id="d03"></a>

## D03｜到店评价与消费评价分开

- **问题：**一次到店互动能否解锁商品评价？
- **当前选择：**地点评价依赖登记终端与有效打卡；商品评价另需真实支付核验。
- **明确不做：**不把客户端“支付成功”字段或历史模拟订单当成付款证明。
- **代价：**演示不能宣称支付闭环已完成，商家可用功能较少。
- **下一步依据：**先确定支付渠道与商户资质，再定义下单、验签、查单、退款与评价资格变化。

<a id="d04"></a>

## D04｜恢复原结果，而不是自动重做

- **问题：**网络失败时，用户无法判断请求是否已经执行。
- **当前选择：**保留原操作标识及安全检查点，重新查询原会话；已完成返回原结果和奖励快照。
- **代价：**状态更多，需要处理“未知”而不是只设计成功页。
- **验收：**重复确认、重复评价、会话恢复及结果隔离；提交回执丢失不自动重放。
- **边界：**检查点尚未保存的窗口、真机系统存储及实际断网仍需专项验证。

## D05｜纪念价值先于真实上链

- **问题：**用户是否真的需要链上资产，还是只需要保留共同经历？
- **当前选择：**默认先保存不上链的数字纪念凭证，真实链服务作为后续能力。
- **代价：**不能以“已发行区块链 NFT”宣传，也不能用技术想象代替用户价值。
- **待验证：**无积分刺激时，用户是否仍愿意查看或保存相遇记录。联盟链技术选择本身不构成合规结论。

## D06｜可靠性是交付门槛，但不是产品成功指标

- **问题：**注册丢失、重复奖励和恢复失败会破坏用户对结果的信任。
- **已交付：**事务、TLS、备份恢复、容器持久性等可追溯验收。
- **代价与复盘：**工程验证投入较多，而用户价值研究尚无可核验结果；下一轮不应继续只扩展技术测试。
- **下一步：**以用户完成核心任务为先，把技术验收作为必要约束，而不是把测试数量当成留存或需求验证。
